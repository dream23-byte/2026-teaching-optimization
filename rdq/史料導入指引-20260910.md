# 史料導入指引 — 內建史料集（Phase 1）

> 目的：建立「AI 優先參考的內建史料集」，降低幻覺、加快回答。
> 檢索層級（老師建議）：內建史料集 → 史料庫網站 → 才上網搜尋。

## 檔案放哪裡

- 資料夾：`史料/`
- 支援格式：`.md`、`.txt`（最快）；`.docx`／`.pdf` 需轉成前二者之一再放
- 請勿放 `_` 開頭的檔案（保留字，系統會跳過）

## 檔案格式約定

每個檔案 = 一份史料，建議依此結構：

```markdown
# 《出處或書名》——主題簡稱

**出處**：《書名或機構》／作者／年代
**性質**：史料全文或整理摘要

---

正文內容……（分段，空一行隔開；每段 60 字以上，最長 1800 字）
```

## 命名建議

- 開頭放事件/主題關鍵字，方便以後人工辨識：
  - `馬關條約全文.md`
  - `二二八事件-調處委員會報告節錄.md`
  - `史記-秦統一六國-節錄.md`

## 優先順序（現階段）

1. **臺灣史高爭議、高幻覺風險事件**：二二八、戒嚴/遷臺、馬關條約、1996 直選、荷治/明鄭（課堂最需要客觀史料）
2. **中國史事件量最大**：秦漢、三國、魏晉南北朝、隋唐、宋元明清常考點
3. **世界/日本**：明治維新、大航海時代、兩次世界大戰相關
4. 不限此清單，手邊有的先丟，品質以「能標明出處」為準

## 匯入流程（交給 AI 助手執行）

1. 你把史料檔案放進 `史料/`
2. 告訴 AI：`跑史料導入`
3. AI 會執行 `tools/build_source_index.js`（用 Gemini 產出每段的摘要、關鍵詞、標題），再把結果寫入 Supabase `source_texts` 表
4. `source_texts` 資料載入前端後，AI 回答問題時就會優先參考命中史料，並以 `〔史料：《標題》〕` 標註引用

## 注意事項

- 首批 10–15 份即足夠驗證效果，不用一次大量灌
- 檔案內容避免贅字物件（網頁複製的 CSS/廣告等），請貼純文字
- 敏感史料的用語維持中性，AI 約束會要求多方觀點
