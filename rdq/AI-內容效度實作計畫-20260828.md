## A. RAG / 史料庫約束（核心，優先）

### A1. 前端撈取 event_sources + sources
- 在 Supabase 初始化附近（`periods` / `historical_events` 查詢後）新增查詢，把事件相關史料拉回並建索引。
- 建議緩存於 module 變數：`var sourcesByEvent = {}`（key = event id，value = 史料陣列）。
- 查詢方式（一次撈全部，前端 join，量小）：
```sql
select s.id, s.title_zh, s.source_name, s.creator, s.date,
       s.source_url, s.language, s.description,
       es.event_id
from sources s
join event_sources es on es.source_id = s.id
```

### A2. buildEventContext() 注入史料
- 在現有 context 尾部（「同時期世界脈絡」之後）加：
```
【相關史料】
• 《title_zh》（source_name，creator，date）：description
```
- 只帶入該事件對應史料（`sourcesByEvent[ev.id]`），最多 3–5 筆控制 token。

### A3. 系統指令統一加史料約束
- 三個 persona（socratic / comparative / roleplay）的 `systemPrompt` 尾部加同一段：
```
【史料約束】回答歷史問題時，必須優先依據對話紀錄中提供的「相關史料」與事件描述作答；
若史料不足或與提問無關，必須明確說明「依據現有所知，無法確認」，不得編造具體史料原文、頁碼或來源。
```
- 同時解決「不當引用」與「幻覺」問題。

### A4. 來源引用顯示（可選，加分項）
- 要求 AI 回應中引用史料時以 `〔史料：title_zh〕` 標記。
- 前端 `appendMessage` 用 regex 把標記轉成可點擊資料卡或純文字高亮。
